## What this is

A fully static, dependency-free personal website — portfolio, articles, and a linktree-style page, all generated from Markdown with [Pandoc](https://pandoc.org/) and a handful of small Python scripts. No JavaScript, no client-side frameworks, no build tools beyond what's already on a typical Linux machine.

### Highlights

- **Zero JavaScript.** Every interactive-feeling element (image galleries, hover states, dark mode) is pure HTML/CSS.
- **Markdown-first publishing.** Every post, project, and page is written in Markdown with a small YAML front matter block, and turned into HTML with one command.
- **Unified content pipeline.** Portfolio projects, blog articles, and tutorials all go through the same publishing script — the only difference is a `type:` label.
- **Tagging system with selective RSS.** Posts can carry `topic/` and `subtopic/` tags; only topics get their own RSS feed, keeping subscriptions meaningful instead of overwhelming.
- **Auto-generated everything that can break.** The homepage grid, the posts index (paginated), the tag pages, the RSS feeds, and the 404 page are all generated by scripts — never hand-edited, never out of sync.
- **Reusable by design.** The "engine" (`publish.sh`, `scripts/`, `templates/`, `style.css`) is fully decoupled from personal content (`site.config`, `content/`, `posts/`). See [TEMPLATE-README.md](TEMPLATE-README.md) if you'd like to fork this and build your own site on top of it.

## Stack

| Piece | Tool |
|---|---|
| Markdown → HTML | [Pandoc](https://pandoc.org/) |
| Automation (feeds, tags, pagination, home/links generation) | Python 3 (standard library only) |
| Publishing | A single Bash script (`publish.sh`) |
| Styling | Hand-written CSS, no framework |
| Hosting | GitHub Pages + GitLab Pages (mirrored) |
| Version control | Git, mirrored to both GitHub and GitLab |

No Node.js, no npm packages, no static site generator, no database, no server-side code of any kind.

```
│       └── media/         # Images/video, co-located with their post
├── about/                # The About/CV page
├── links/                # Generated linktree page
├── tags/                 # Generated tag pages + per-topic RSS feeds
├── templates/            # Pandoc templates (post, page)
├── scripts/              # Python generators (feed, tags, home, links, 404, chrome)
├── style.css             # The entire design system
├── publish.sh            # The one command that ties it all together
└── feed.xml              # Site-wide RSS feed
```

## Publishing workflow

```bash
# Write a new post
mkdir -p posts/my-post
nano posts/my-post/my-post.md

# Publish it — regenerates the post, the feed, tag pages, homepage, links, and 404
./publish.sh posts/my-post/my-post.md

# Ship it
git add .
git commit -m "New post: My Post"
git push origin master
git push gitlab master
```

Front matter is intentionally minimal:

```yaml
---
title: My Post
type: Article
date: 2026-01-01
tags:
  - topic/art
  - subtopic/blender
portfolio: true
---
```

- `type` is a free-form label — used for display and grouping, not for choosing a template.
- `tags` follow a `topic/` / `subtopic/` convention: topics get their own RSS feed at `/tags/<name>/feed.xml`; subtopics are for filtering only.
- `portfolio: true` adds the post to the homepage grid automatically.
- Posts without a `date` are excluded from RSS feeds (to avoid breaking chronological order with a guessed date), but still show up in `/posts/`.
